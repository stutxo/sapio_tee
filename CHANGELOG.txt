0.2.0 — 2026-09-18

- Build the enclave image around a minimal defconfig-based kernel (Nitro
  virtio/vsock/NSM options built in) instead of nixpkgs' all-driver common
  config, and reclaim runner disk before the EIF build: GitHub's ubuntu
  runners previously ran out of space mid-kernel-compile.

- Cache the nix store and cargo artifacts in CI: repeat pushes restore the
  kernel, odyn, and rust compilation instead of rebuilding them.

- Target aarch64: the enclave image, supervisor, and parent runner are now
  cross-compiled for Graviton Nitro Enclaves from the x86_64 build host —
  arm64 defconfig kernel (`Image`), aarch64 musl statics, aarch64 init and
  busybox. Local development remains native x86_64.

- Deploy Sapio's ProgramOracle inside x86_64 AWS Nitro Enclaves, using
  SignProgramV1, bounded inline WASM v1/v2 and a measured pay-at-least/v1
  interpreter.
- Recover the BIP32 root through attested KMS ECDH and settings-bound HKDF.
- Bind the public identity and signing profile to a fresh NSM challenge.
  Verify against independently trusted measurements, settings and profile.
- Provide offline program-profile output, pinned EIF/runner builds,
  restrictive KMS policy generation and deployment/recovery guidance.
- Include a runnable ProgramClient example demonstrating flexible payments,
  key-path and script-path signatures, inline predicates and failed requests.
- Verify signing on native and musl services, signed-document acceptance and
  rejection cases, and a complete EIF build. See VERIFICATION.txt for evidence.
- Real Nitro boot, live KMS provisioning and hardware recovery remain
  unverified; local software checks are not production-custody assurance.
