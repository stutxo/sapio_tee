Unreleased

- Attach an Elastic IP to the test parent: the public oracle keeps one stable
  address across instance replacement and stop/start. The ssh_tunnel output
  and public_ip now refer to it.

- Add optional public test-oracle exposure: public_api_cidr opens security
  group ingress on enclave ports 8000 and 8367 and skips the host firewall
  REJECT for them. Empty (the default) keeps the previous tunnel-only
  posture. Documented as unauthenticated, unencrypted, test-network-only,
  with a hostile-first-setup race window after restarts.

- Fix the first-live-boot defect: the cross-built enclave init was dynamically
  linked against a Nix-store glibc. Current nixpkgs buildGoModule manages
  env.CGO_ENABLED itself and drops the pinned package's legacy integer
  attribute, so the intended CGO_ENABLED=0 never applied; PID 1 could not
  exec inside the enclave and nitro-cli reported E36 with an empty guest
  console. Build the init against musl with a fully static external link and
  assert no INTERP segment at build time so this cannot silently regress.
  The EIF and its measurements change; a redeploy updates the PCR-bound KMS
  policy in place and replaces the disposable parent.
- Add kms:GetKeyRotationStatus to the generated policy's admin statement: the
  Terraform AWS provider reads it after CreateKey, and the first live apply
  deadlocked on state refresh without it. It is read-only and asymmetric keys
  cannot rotate. Recovery: manual terraform-mode PutKeyPolicy, untaint,
  converged re-apply.
- Record the first live Nitro deployment evidence (signet): real boot with
  describe-enclaves PCRs matching the build, attested KMS derivation, a
  genuine NSM document verified by the hardened verifier against independent
  measurements and the AWS root, all 17 signing scenarios against the
  verified identity, byte-identical root recovery across a service restart,
  and an explicitly denied unattested DeriveSharedSecret. This is one
  operator run, not third-party reproduction or a production assurance.

- Harden the attestation verifier after independent review: verify() itself
  now requires exactly the PCR0/1/2 pin set rather than relying on its CLI
  caller, and the verified xpub is base58check-decoded, matched against the
  BIP32 version bytes of the claimed settings network, and required to carry a
  valid secp256k1 key. Fix tag-18-wrapped COSE documents failing closed on
  cbor2's frozendict decoding of the tagged unprotected header. Add negative
  certificate-path tests (expired/not-yet-valid leaf, non-CA issuer, expired
  root, wrong curve) and rejection tests for future timestamps, missing
  challenge, wrong digest, ambiguous or non-ES384 COSE algorithms, non-Sign1
  tags, duplicate JSON fields, trailing CBOR, malformed/cross-network xpubs
  and missing/partial measurement pins; 27 tests total.
- Repair and hash-pin the verifier requirements: pyOpenSSL==26.3.0 declares
  cryptography<50, so the previous cryptography==50.0.0 pin could not resolve.
  Pin the compatible pyOpenSSL==26.4.0 / cryptography==50.0.1 pair plus the
  full cffi/pycparser/typing-extensions closure with per-artifact SHA-256
  hashes, and install with pip --require-hashes. Verified by a fresh-venv
  hash-enforced install running the complete attestation test suite.
- Bound the vault sweep output to at least 330 satoshis (the P2TR dust floor):

  destination, so an under-proportioned deposit cannot be burned entirely to

  061469c24ae73a0cbf1400d6dc57093d60a49143de1c6a0181ba7c3162c378be), updated
  its provenance, and added reject/accept boundary cases to the live example.
  The program identity changes; no funded contract exists to migrate.

0.2.0 — 2026-09-18

- Build the enclave image around a minimal defconfig-based kernel (Nitro
  virtio/vsock/NSM options built in) instead of nixpkgs' all-driver common
  config, and reclaim runner disk before the EIF build: GitHub's ubuntu
  runners previously ran out of space mid-kernel-compile.

- Cache the nix store and cargo artifacts in CI: repeat pushes restore the
  kernel, odyn, and rust compilation instead of rebuilding them.

- Target aarch64: the enclave image, supervisor, and parent runner are now
  cross-compiled for Graviton Nitro Enclaves from the x86_64 build host —
  arm64 defconfig kernel (`Image`), aarch64 musl statics, aarch64 init and
  busybox. Local development remains native x86_64.

- Deploy Sapio's ProgramOracle inside x86_64 AWS Nitro Enclaves, using
  SignProgramV1, bounded inline WASM v1/v2 and a measured pay-at-least/v1
  interpreter.
- Recover the BIP32 root through attested KMS ECDH and settings-bound HKDF.
- Bind the public identity and signing profile to a fresh NSM challenge.
  Verify against independently trusted measurements, settings and profile.
- Provide offline program-profile output, pinned EIF/runner builds,
  restrictive KMS policy generation and deployment/recovery guidance.
- Include a runnable ProgramClient example demonstrating flexible payments,
  key-path and script-path signatures, inline predicates and failed requests.
- Verify signing on native and musl services, signed-document acceptance and
  rejection cases, and a complete EIF build. See VERIFICATION.txt for evidence.
- Real Nitro boot, live KMS provisioning and hardware recovery remain
  unverified; local software checks are not production-custody assurance.
